# 요구사항 정의서 (Software Requirements Specification)

**프로젝트:** 치즈보드 (CheeseBoard)  
**작성일:** 2026-04-22  
**최종 수정:** 2026-05-15  
**상태:** 초안

---

## 1. 배경 및 문제 정의

치지직(CHZZK)은 다음과 같은 검색/탐색 한계를 가진다.

| 문제 | 상세 |
|---|---|
| 클립 검색 불가 | 치지직 자체 검색에서 클립은 검색 대상이 아님 |
| 과거 영상 탐색 불편 | 특정 영상을 찾으려면 채널에서 무한 스크롤을 반복해야 함 |
| 이전 시청 기록 재탐색 | 예전에 봤던 영상을 다시 찾기 어려움 |

치즈보드는 VOD와 클립을 키워드·스트리머·정렬 기준으로 빠르게 탐색할 수 있는 외부 검색 서비스를 제공한다.

---

## 2. 사용자 정의

**주요 사용자:** 치지직을 즐겨보는 일반 시청자

| 유형 | 설명 |
|---|---|
| 탐색형 | 인기 클립을 둘러보다가 재밌는 것 발견 |
| 재시청형 | 예전에 봤던 영상을 다시 찾아보고 싶음 |
| 발굴형 | 재밌었던 경기, 합방 등 특정 이벤트를 키워드로 찾고 싶음 |

---

## 3. 핵심 사용자 시나리오

**시나리오 1 — 인기 클립 탐색**
> 사이트 진입 → 인기 클립 피드 노출 → 클릭 → 사이트 내 iframe 재생

**시나리오 2 — 재시청**
> 사이트 진입 → 키워드 검색 → 결과에서 해당 영상 확인 → 클립이면 iframe 재생 / VOD이면 치지직 새 탭

**시나리오 3 — 과거 이벤트 발굴**
> 사이트 진입 → 스트리머 선택 또는 키워드 검색 → 정렬(날짜/조회수) → 목록 탐색 → 클립이면 iframe 재생 / VOD이면 치지직 새 탭

## 4. 기능적 요구사항

### Phase 1 (MVP)

| ID | 기능 | 상세 |
|---|---|---|
| FR-01 | 인기 클립 피드 | 메인 페이지에 조회수 기준 인기 클립 목록 노출 |
| FR-02 | 키워드 검색 | 영상 제목, 태그를 대상으로 한국어 형태소 분석 기반 검색 |
| FR-03 | 스트리머 필터 | 특정 채널의 VOD/클립만 필터링 |
| FR-04 | 정렬 | 조회수순(인기), 날짜순(최신) 정렬 |
| FR-05 | VOD/클립 구분 | 탭 또는 필터로 VOD와 클립 분리 탐색 |
| FR-06 | 영상 재생 | 클립: iframe 임베딩 재생 / VOD: 치지직 원본 페이지 새 탭 |
| FR-07 | 치지직 링크 | 원본 영상 페이지로 바로가기 |
| FR-10 | 로그인 | 네이버 아이디로 로그인 (OAuth 2.0) |
| FR-11 | 댓글 | 영상에 의견 남기기 (로그인 전제) |
| FR-12 | 태그 기여 | 사용자가 영상에 태그 추가 (로그인 전제). 추가된 태그는 Elasticsearch 인덱스에 반영되어 검색 결과에 기여. 정규식 + 블랙리스트 기반 비속어 필터링 적용 (추후 LLM 분류로 확장 예정) |

### Phase 2 (MVP 이후)

| ID | 기능 | 상세 |
|---|---|---|
| FR-13 | 외부 영상 연동 | 커뮤니티 사이트 등 외부 출처 영상 포함 (범위 미정) |
| FR-14 | 스트리머 자동 확장 | 실시간 방송 상위 N명을 주기적으로 서비스 범위에 편입 |
| FR-15 | 주제별 모아보기 | 관리자가 큐레이션한 주제(Topic) 단위로 VOD/클립을 묶어 노출. 사용자는 주제 목록 및 상세 페이지에서 탐색 |
| FR-16 | 관리자 페이지 | 주제 CRUD, 영상 큐레이션, 사용자 태그 모더레이션 등 운영 기능. 화이트리스트 기반 접근 제어 |

## 5. 비기능적 요구사항

| 항목 | 요구사항 |
|---|---|
| 검색 성능 | Elasticsearch + 한국어 형태소 분석기(nori)로 빠른 full-text 검색 |
| 응답 속도 | 특정 목표값 없음. 일반적인 웹 수준이면 충분 |
| 지원 스트리머 수 | 초기: 뷰어십 기준 상위 400명. 이후 방송 중인 상위 N명을 주기적 업데이트 |
| 반응형 웹 | 모바일 필수 지원. 별도 앱 없이 웹앱(반응형) 형태 |
| 플랫폼 | 웹 브라우저 (PC + 모바일) |

## 6. 기술 스택 결정사항

| 서비스 | 스택 | 비고 |
|---|---|---|
| 스크래퍼 | Python, FastAPI, httpx, Pydantic | CHZZK API 수집 후 DB/ES에 저장 |
| 백엔드 | Spring Boot, PostgreSQL, Elasticsearch, Redis | 검색은 ES, 원본 데이터는 PostgreSQL, API 응답 캐싱은 Redis |
| 프론트엔드 | React, TypeScript, Vite, TanStack Query, Tailwind CSS | 반응형 웹 |

**데이터 흐름:**
```
CHZZK API
    ↓
FastAPI 스크래퍼
    ├→ PostgreSQL  (원본 데이터 저장)
    └→ Elasticsearch (검색 인덱스)
            ↓
       Spring Boot  ← React 프론트
```

## 7. 제약사항 및 전제

| 항목 | 내용 |
|---|---|
| 크롤링 허용 | 치지직 robots.txt: `Allow: /` — 전면 허용 |
| 데이터 저장 범위 | 영상 파일 저장 없음. 메타데이터(제목, 조회수, 태그, 영상 ID)만 수집 |
| 상업적 목적 | 없음 (비상업적 개인 프로젝트) |
| 법적 면책 | 서비스 내 치지직과 무관한 제3자 서비스임을 명시하는 문구 표시 |
| CHZZK API | 비공식 API 사용. 언제든 변경/차단될 수 있으므로 스크래퍼 레이어를 분리하여 대응 용이하게 유지 |
